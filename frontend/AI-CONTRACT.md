# Qadam: контракт AI для Go backend

Frontend подготовлен к трём AI-возможностям: уточняющие вопросы, голосовой ввод
и чат-помощник. Все три endpoint реализованы в Go. Базовый URL — `/api`, формат
успеха `{ "data": ... }`, ошибки — `{ "error": { "message": "..." } }`.

Frontend преобразует локальные `demo-business-1`, `team-1`…`team-5` в заголовок
`X-Demo-Actor: business:UUID` / `team:UUID`. У гостя заголовок отсутствует.
Это демонстрационный выбор роли, не настоящая авторизация.

## 1. Голосовой ввод

`POST /api/ai/transcribe`, `multipart/form-data`:

- `audio`: один файл `webm`, `m4a/mp4` или `ogg`, запись до 60 секунд;
- `context`: строка до 1000 символов с текущим вопросом или названием задачи;
- `languages`: `ru,kk` — языковые подсказки.

Успех:

```json
{
  "data": {
    "text": "Управляющий вручную проверяет остатки в таблице.",
    "language": "ru"
  }
}
```

Backend ограничивает тело запроса 15 MiB, проверяет сигнатуру контейнера,
ставит timeout 60 секунд, удаляет временные файлы и не сохраняет запись.
Запись передаётся в `/v1/audio/transcriptions`; модель задаётся через
`OPENAI_TRANSCRIBE_MODEL` (по умолчанию `gpt-4o-mini-transcribe`). Контекст передаётся
как prompt, язык определяется автоматически. API-ключ остаётся только в окружении Go.

Ошибки: 400 неподдерживаемый формат, 413 слишком большой файл, 422 пустая речь,
429 лимит запросов, 503 провайдер недоступен. Ошибка не должна очищать текст формы.
Сырые записи не сохранять и не логировать. Возвращать только plain text.

## 2. AI-вопросы и сборка карточки

`POST /api/ai/analyze`:

```json
{
  "stage": "clarify",
  "sources": [{"id":"draft","text":"Описание бизнеса"}],
  "currentFields": {}
}
```

Для `clarify` ответ содержит 3–5 вопросов, созданных по конкретному описанию:

```json
{
  "data": {
    "mode": "live",
    "questions": [
      {"id":"q1","text":"Кто принимает решение о закупке?","fieldKeys":["users"]}
    ],
    "fieldSuggestions": [],
    "warnings": []
  }
}
```

Для `assemble` — предложения полей `{field,value,sourceId}`. Значение должно
подтверждаться переданным источником. Frontend принимает только `mode: "live"`:
шаблонные вопросы не показываются как ответ AI. При ошибке доступно явное ручное
заполнение карточки.

## 3. Чат Qadam AI

`POST /api/ai/chat`:

```json
{
  "messages": [{"role":"user","content":"Как описать ожидаемый результат?"}],
  "context": {"page":"/tasks/20000000-0000-4000-8000-000000000001","taskId":"20000000-0000-4000-8000-000000000001"}
}
```

Ответ: `{ "data": { "reply": "..." } }`. До 19 сообщений в истории, вопрос
до 2000 символов, ответ до 12000. Роли только `user` и `assistant`. System prompt
задаёт backend: помощник объясняет Qadam, помогает сформулировать задачу или
предложение, не выдумывает статус проекта и не совершает действия от пользователя.

Весь пользовательский текст и taskId считаются недоверенными. Если backend добавляет
контекст задачи, использовать только публичные поля или данные выбранного demo-actor.
Ответ — plain text; frontend не исполняет HTML.

## Приёмка интеграции

1. Русская и казахская запись превращаются в редактируемый текст.
2. Запрет микрофона, тишина и недоступный провайдер дают понятную ошибку и повтор.
3. Из двух разных описаний `/ai/analyze` создаёт разные релевантные вопросы.
4. Ответы голосом добавляются к соответствующему вопросу и входят в `sources`.
5. Чат отвечает с контекстом текущей страницы; ошибка сохраняет вопрос для повтора.
6. Ключи OpenAI/NVIDIA отсутствуют в frontend, JSON, логах и Git.

Файловая транскрибация `webm` поддерживается официальным OpenAI API:
https://developers.openai.com/api/docs/guides/speech-to-text
